# Linmas 0.9.3

Linmas 0.9.3 is a correctness and hardening release for the local paths: the CLI, policy packs, the MCP error contract, and proof bundles. It adds no provider features and does not change how a live review is sent.

## Fixed

- Interactive confirmation for `linmas review` and `linmas proof create` now works in a real terminal. Earlier releases refused every run without `--yes`. Lines typed before the prompt appears are discarded.
- A policy pack is loaded and matched against the selected skill and mode before the provider is called, in both the CLI and `linmas_review_execute`; a mismatch is an input error and nothing is transmitted.
- MCP review errors report the real transmission state instead of always claiming an attempt, and every tool error maps to a documented public code in `mcp/ERRORS.md`.
- The MCP provider preview reports `authMode: "unverified"` when a provider is configured; it never verified a login.
- A provider response that is valid JSON but not an object is reported as an invalid response instead of crashing.
- An unreadable capsule is reported as `INVALID_PATH`.

## Hardened

- `proof verify --allowed-signers` requires a valid signature from a listed signer, and the signing principal must match the reviewer recorded in the decision receipt. The verified principal is shown.
- `proof verify` rejects bundle files that the manifest does not list, and reads `signature/signer.pub` and `signature/manifest.sig` only as bounded regular files.
- `proof create` claims its destination exclusively and never replaces an entry created by another process.
- Policy rule `severities` and `statuses` must be exact ReviewResult values.
- Text output escapes control, bidi, and invisible characters in untrusted values, and prefixes continuation lines of provider text, across `review`, `review compare`, policy results, `proof`, and the host commands.
- `report.md` escapes HTML and Markdown in free text.

## Added

- `linmas --help` (`-h`) and `linmas --version` (`-v`).
- A prepare-only `linmas review` states that no review was run and how to run one.
- `linmas_review_decide` results carry `reviewInteraction.elicitationConfirmed`.
- New public MCP error codes: `INTERNAL_ERROR`, `DECISION_INPUT_REQUIRED`, `RISK_ACKNOWLEDGEMENT_REQUIRED`, `ARTIFACT_WRITE_FAILED`, `SIGNATURE_VERIFICATION_FAILED`, and `POLICY_RESULT_INCOMPATIBLE`.

## Upgrade notes

These changes can reject input that 0.9.2 accepted:

- `proof verify --allowed-signers` fails with exit code 4 for an unsigned bundle instead of labelling it `unsigned`.
- `proof verify` fails for a bundle containing files outside its manifest, including `.DS_Store` and empty directories.
- A custom policy file with an unknown or differently cased severity or status fails validation.

MCP clients that matched on `authMode: "configured"` or on the previous catch-all `INPUT_FIELD_INVALID` code for internal, decision, write, and signature failures should update to the values above. Text output of `linmas review` now indents continuation lines with `  | `; JSON output is unchanged.

Install or upgrade with Node.js 24 or newer:

```bash
npm install --global linmas@0.9.3
linmas --version
```

This release was verified with offline tests only. No live provider review was run for it, and it does not establish live provider, MCP host, or production runtime behavior. Proof-bundle writing on Windows is not tested on Windows.
