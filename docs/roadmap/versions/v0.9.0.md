# v0.9.0 Roadmap Outcomes

Status: **UNRELEASED**. The outcomes below define reviewable contracts and positive/negative cases; they are not execution results or a release promise.

## 1. Bind evidence to the reviewed revision

Positive case: candidate metadata and evidence refer to the same implementation revision. Negative case: a stale or different HEAD is rejected.

## 2. Require complete, distinct evidence results

Positive case: each record has both expected and observed results, with a revision-bound evidence location and limitation. Negative case: missing required fields, stale evidence, or a mismatched claim level is rejected.

## 3. Keep canonical inventories exact

Positive case: the source skill and MCP inventories exactly match their canonical definitions, and every MCP operation has one operation-bound semantic test locator. Negative case: a missing or duplicate inventory entry, or a missing, unrelated, or generic test reference, is rejected.

## 4. Preserve the Windows destructive-operation denial

Positive case: destructive uninstall remains `UNSUPPORTED` when safe handle-relative filesystem mutation is unavailable and reports `SAFE_FILESYSTEM_OPERATION_UNAVAILABLE`. Negative case: replacing that denial with a success claim is rejected.

## 5. List all seven MCP operations in the runbook

Positive case: the runbook contains exactly the seven operations exposed by source. Negative case: a missing, duplicated, or drifted operation is rejected.

## Compatibility limits

Codex and Claude Code host loading, Hermes format loading, and live provider/model evaluation remain `UNKNOWN` or OUT OF SCOPE without separately collected runtime observations. Source or deterministic-fixture evidence cannot be promoted to an actual-runtime claim.

## 12. Implementation Checklist

- [ ] Record the reviewed implementation revision and tree, baseline commit/tag identity, and environment in revision-bound evidence.
- [ ] Reconcile version `0.9.0` across package metadata, the lockfile root, the plugin package, and the plugin manifest; retain expected and observed results separately.
- [ ] Verify evidence locations against the reviewed source and all seven MCP operations before interpreting a result.
- [ ] Retain `UNKNOWN` for unobserved host and live-provider behavior, `UNSUPPORTED` for Windows destructive uninstall, and `NOT TESTED / OUT OF SCOPE` for TAC Business.
- [ ] Obtain independent review of the exact draft bytes before requesting authorization for local construction.
