# Linmas v0.9.0 Implementation Notes

Status: **UNRELEASED**. These notes summarize source contracts; they do not report a validation run or authorize publication.

## Operating model

The MCP server exposes seven bounded operations with strict input schemas, workspace-confined paths, and bounded timeouts. Local preparation and evidence operations are distinct from actions that write a proof bundle or transmit input to a provider. Human review remains required for review results.

## Tool contract

| Operation | Contract boundary |
| --- | --- |
| `linmas_review_prepare` | Prepares a bounded offline request; it does not call a provider or write files. The result remains subject to human review. |
| `linmas_review_compare` | Validates and compares two local capsules. An absent finding is not proof of remediation. |
| `linmas_policy_evaluate` | Evaluates one selected local policy against a validated capsule; this is not approval or certification. |
| `linmas_proof_verify` | Checks local bundle integrity, signature classification, source binding, and the human-review boundary; it does not establish authorship or correctness. |
| `linmas_proof_create` | Requires `confirm_write: true` and a new output path; it makes no proof-of-impact claim. |
| `linmas_review_execute` | Requires explicit transmission consent before provider execution. Results remain advisory and require human review. |
| `linmas_review_decide` | Binds a disposition to an in-memory review handle and capsule digest. Caller-supplied severity cannot replace the immutable review. Critical/High continuation requires explicit risk acknowledgement and rationale; it is not a security approval. |

## Resource and safety limits

The implementation bounds input text to 64 KiB, paths to 512 characters, output to 256 KiB, MCP lines to 512 KiB, capsules to 2 MiB, and proof trees to 32 MiB. Read, write, and transmit operations have separately bounded timeouts. These are source constants, not measured performance results.

On Windows, destructive uninstall is deliberately unsupported when secure handle-relative mutation is unavailable; the code returns `SAFE_FILESYSTEM_OPERATION_UNAVAILABLE` before destructive work.

## Evidence boundary

Source and deterministic-fixture assertions can establish only their stated code/test behavior. They do not establish host loading, actual runtime compatibility, live model quality, or release readiness. Preserve those states as `UNKNOWN` or OUT OF SCOPE until separately observed and reviewed.
